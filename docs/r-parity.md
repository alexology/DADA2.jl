# Fidelity to DADA2 R

DADA2.jl translates the R and C++ code of DADA2 1.36.0 (upstream commit
`b61fe2e90115be08e78a01a16af89fd21402ca42`) for filtering, dereplication,
denoising, error learning, pair merging and chimera detection. Iteration
order, tie-breaking and the order of floating-point operations follow
upstream wherever they can change a result. This page lists what has been
checked against R, the deliberate differences and what is missing.

All checks use R 4.5.0 and dada2 1.36.0 on Windows, Julia 1.12.2.

## What is checked

| Area | Reference | Result |
| --- | --- | --- |
| Aligners (vectorized ends-free, classic, homopolymer, global) | 5,000 random pairs; 400 kept in `test/fixtures/core/nwalign.tsv` | identical alignments |
| `dada` with a fixed error model | 98 simulated samples, 14 option sets, up to 4,152 uniques; 14 kept in `test/fixtures/core` | identical ASVs, abundances, per-unique map, transition counts and `$clustering` |
| `loessErrfun` (interpolated `loess`) | 300 random transition matrices, sparse and binned qualities | relative difference ≤ 1.1e-12 |
| `learnErrors` | real fixture and 2–8 simulated samples, `nbases` budgets on files and dereplicated samples, `pool=TRUE` and `"pseudo"`; kept in `test/fixtures/learn` and `test/fixtures/pipeline` | same rounds, identical transitions (see pooled learning below), rates within 1e-12 |
| Pooling and pseudo-pooling | 4 samples with shared rare variants, plus 5 random sets; `test/fixtures/pipeline` | identical per-sample ASVs, maps and diagnostics |
| `mergePairs` | default, `maxMismatch=2`, `trimOverhang`, `justConcatenate`, plus 5 random sets | identical pair tables |
| Chimeras | consensus, pooled, per-sample, `allowOneOff`, other thresholds and `maxShift`, plus 5 random sets | identical flags and tables |
| `isPhiX` | 600 sequences, 4 parameter sets; `test/fixtures/phix.tsv` | identical |
| Bundled fixture (`sam1F`/`sam1R`) | whole paired-end pipeline | identical final table |
| Real paired-end COI sample, Element AVITI (292,050 pairs, Q up to 45) | whole pipeline | identical filtered reads, ASVs, merges and final table; error models within 1.3e-14 |

Floating-point values agree to rounding: R's `loess` solves with LINPACK and
its Poisson tails come from R's Mathlib, while Julia uses LAPACK and
Distributions.jl (tails below 1e-292 are recomputed in log space, as R does).
No difference in ASVs or counts has been observed from this.

The real sample is private and not distributed; the other references are
regenerated by the scripts below.

## Deliberate differences

- **Long sequences.** Upstream scores alignments in 16-bit integers, which
  overflow from about 6,500 identical bases and lose aligned pairs (also in
  R). Julia uses 32-bit scores whenever 16-bit ones could overflow, so it
  agrees with R whenever R does not overflow.
- **Error-model coverage.** R extends an error model that does not cover the
  qualities by repeating its last column; Julia raises an error.
- **Order of ASVs.** `DadaResult.sequences` is sorted by decreasing abundance;
  R keeps the order in which partitions were created. Indices in
  `clustering.birth_from` refer to Julia's order.
- **Transitions after pooled learning.** With `pool=TRUE`, R's
  `learnErrors(...)$trans` adds the pooled transition counts once per sample,
  because each sample's result carries the pooled matrix; the error model
  itself is estimated from them once. Julia reports the counts once, so
  `errorDiagnostics` shows the real exposures; the error models agree.
- **Births from priors.** Upstream leaves `birth_from` uninitialised for
  partitions created from a prior; Julia reports the parent partition.
- **Raw-quality learning.** `learnErrors(...; qualityMode=:raw)` keeps R's
  procedure but counts transitions at the original read qualities. On the
  real sample it changed error rates up to twofold and shared 298 of 303
  final ASVs; its accuracy is unknown.

Two upstream behaviours are reproduced although they are questionable:
pseudo-pooling infers the second pass with the error model re-estimated from
the first pass instead of the one supplied, and `learnErrors`, like R, stops
with an error if a base is never observed or observed at a single quality.

## Not ported

Primer removal and orientation (`removePrimers`, `orient.fwd`),
low-complexity filtering (`rm.lowcomplex`, `seqComplexity`), PacBio settings,
`collapseNoMismatch`, `isShiftDenovo`, quality and error plots, and other
helpers. Taxonomic assignment (`assignTaxonomy`, `addSpecies`) is an
independent naive Bayes implementation, not R's RDP classifier, and has not
been compared with it.

## Repeating the checks

From the repository root, with R and dada2 installed:

```sh
Rscript validation/core_reference.R      # aligners, dada, $clustering
Rscript validation/learn_reference.R     # learnErrors
Rscript validation/pipeline_reference.R  # pooling, mergePairs, chimeras
Rscript validation/phix_reference.R      # isPhiX
julia --project=. --threads=4 test/runtests.jl
```

The R scripts rewrite the fixtures in `test/fixtures/`; the test suite
compares Julia with them. The bundled paired-end fixture can be compared
end to end with:

```sh
Rscript validation/reference.R
julia --project=. --threads=4 validation/compare.jl
```

To compare a whole pipeline on your own paired-end files, run the same
settings in R and Julia and compare the outputs:

```sh
Rscript benchmark/pipeline_timing.R R1.fastq.gz R2.fastq.gz out
julia --project=. --threads=4 benchmark/pipeline_timing.jl R1.fastq.gz R2.fastq.gz out
julia --project=. benchmark/pipeline_compare.jl out
```

The scripts accept the trimming and truncation lengths as options (see their
headers) and write only to the output directory.
